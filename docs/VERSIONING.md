# ניהול גרסאות ושחרור — TradeOS

> מדריך החלטה: **מתי ואיך מעלים גרסה.** נכתב כך שכל סוכן AI (או מפתח) יידע
> לבד מתי כדאי להעלות את מספר הגרסה, בלי לשאול. אם אתה סוכן שעובד ברפו — **קרא
> את זה לפני שמשחררים לפרודקשן.**

---

## שני מספרים נפרדים — אל תבלבל ביניהם

| | מה זה | מי מעדכן | איפה |
|--|-------|----------|------|
| **APP_VERSION** | הגרסה השיווקית (למשתמש) | ✋ **ידני בלבד** | `src/utils/constants.js` |
| **CACHE_NAME** | מזהה קאש ל-Service Worker | 🤖 **אוטומטי** בכל push ל-main | `public/sw.js` |

- **APP_VERSION** כרגע נעוץ על **`2.1.0`**. הוא לא עולה לבד. עולה רק כשמישהו מחליט.
- **CACHE_NAME** (`tradeos-v###`) עולה אוטומטית בכל דיפלוי ל-main (דרך
  `scripts/bump-version.mjs`) — זה מה שמפעיל את חלון "גרסה חדשה זמינה" ומכריח
  את הדפדפן לטעון קוד חדש. **לא נוגעים בו ידנית.**

**המסקנה:** שחרור רגיל לפרודקשן **לא דורש** לגעת ב-APP_VERSION. ה-CACHE_NAME
יעלה לבד והמשתמשים יקבלו את העדכון. מעלים את APP_VERSION רק כשרוצים להכריז על
גרסה חדשה משמעותית.

---

## מתי להעלות את APP_VERSION? (Semantic Versioning: MAJOR.MINOR.PATCH)

הפורמט הוא `X.Y.Z`. הנה חוקי ההחלטה:

### 🔴 MAJOR — `X.0.0` (למשל 2.0.0 → 3.0.0)
שינוי גדול שמרגיש כמו "אפליקציה חדשה" או שובר תאימות:
- עיצוב-מחדש מלא / שינוי מבנה ניווט (למשל מעבר ל-4 טאבים)
- מעבר תשתית גדול (למשל Firebase → Supabase)
- הסרת פיצ'ר מרכזי או שינוי שמשנה איך משתמשים באפליקציה

### 🟡 MINOR — `X.Y.0` (למשל 2.0.0 → 2.1.0)
פיצ'ר חדש **משמעותי** שהמשתמש ישים לב אליו, בלי לשבור כלום:
- מסך/כלי חדש (סוכן AI, מאמן, כרטיס ביצועים חדש)
- אינטגרציה חדשה (בורסה חדשה, ספק AI)
- יכולת חדשה בולטת

### 🟢 PATCH — `X.Y.Z` (למשל 2.0.0 → 2.0.1)
תיקונים ושיפורים קטנים, בלי פיצ'ר חדש בולט:
- תיקוני באגים
- שיפורי עיצוב/UI קטנים
- שיפורי ביצועים
- שינויי צבע/טקסט

### ❌ מתי **לא** להעלות APP_VERSION
- שינוי פנימי בלבד (refactor, ניקוי קוד, שינוי ב-Worker/אדמין)
- תיקון שאף משתמש לא ירגיש
- → פשוט משחררים, ה-CACHE_NAME יעלה לבד.

**כלל אצבע לסוכן:** אם אתה מתלבט — זה כנראה PATCH או "בלי שינוי". MINOR/MAJOR
שמורים לדברים שהמשתמש **בוודאות** ירגיש. **בכל מקרה של ספק — אל תעלה APP_VERSION,
רק שחרר.** העלאת APP_VERSION היא החלטה של הבעלים (אבי), לא ברירת מחדל.

## איך מעלים APP_VERSION (כשהוחלט)
1. ערוך `src/utils/constants.js` → `export const APP_VERSION = 'X.Y.Z';`
2. זה הכל. אל תיגע ב-CACHE_NAME (הוא עולה לבד ב-main).
3. שחרר כרגיל (dev → main).

---

## תהליך השחרור לפרודקשן (מזכיר — ראה גם CLAUDE.md)
```
feature/fix branch → PR → dev  →  (בדיקה בסטייג'ינג)  →  PR → main  →  🚀 פרודקשן
```
- **מרג' רק ל-dev** קודם. הבעלים מאשר לפני קידום ל-main.
- push ל-main = בנייה + bump אוטומטי של CACHE_NAME + דיפלוי Hosting (live) + Worker (פרודקשן).
- rollback: Firebase Hosting → Release history → Rollback (שניות).
