Design system · proposal

One interface language for a Hebrew trading terminal.

An audit of TradeOS as it exists today, and a token-driven system that keeps what already works — the true-black canvas, the electric-blue accent, the tabular numbers — while removing the drift. Dark first, RTL native.

Audited at v2.3.1 · 3a70c50 2 themes · 1 accent · 1 typeface family Read-only audit — no product code changed
The audit

What the shipped CSS and components actually say — tokens, type sizes, radii, shadows and the patterns that repeat.

The system

Three token layers, a 12px type floor, one radius per role, and focus and contrast values that are measured, not guessed.

The migration

A one-to-one map from today's class names to the new tokens, ordered so nothing breaks while the old names still resolve.

01 · Principles

Five rules that settle most decisions

These are the judgement calls the system exists to remove. When two options look equally plausible, one of these rules breaks the tie.

01

One accent, one meaning

Blue means action, selection or focus. It never decorates a static surface. Profit, loss and breakeven are data colours and never become UI chrome.

02

Edges before shadows

Depth comes from a hairline border plus one inset highlight. Shadows never grow or move on hover — they repaint neighbours and read as layout shift.

03

Numbers are data, not text

Every figure is tabular and isolated as a left-to-right run, so the minus and the shekel sign stay where they belong inside a right-to-left page.

04

RTL is structural

Layout uses logical properties. Only direction-bearing icons mirror. Nothing is positioned with a physical left or right offset.

05

One surface, one radius

A card is 14px everywhere. A control is 10px everywhere. A page panel is 20px everywhere. Role decides the value, not the page's age.

2.5 Findings

01

The accent is half-migrated

Comments still describe a violet→cyan gradient; the gradient is blue→cyan; violet survives in the light page glow, the sidebar's active wash and the logo mark. Three different “brand” stories coexist.

index.css · .light body, Sidebar ActiveBar, BrandMark
02

The smallest type is the most common

10–11px accounts for 641 occurrences; 8–9px adds 65 more. On a 390px phone those labels are half the comfortable reading size.

text-[10px] 301 · text-[11px] 340 · text-[9px] 53 · text-[8px] 12
03

Shape has no owner

Cards use 12px on one page and 16px on another; inputs use 8px; buttons use 12px; pills use full. The radius carries no meaning.

rounded-lg 492 · rounded-xl 406 · rounded-2xl 159 · rounded-full 327
04

Focus is a border, not a ring

Fields change border colour on focus with no offset ring, and buttons define no focus-visible state at all. Keyboard users get a 1px hue shift on a dark surface.

focus:border-accent-primary · Button.jsx has no focus styles
05

Light mode inherits dead colours

The light theme overrides accents and status colours correctly, but the datepicker and page glow still reference pre-rebrand cyan and violet values that are not in the token set.

rgba(2,132,199,…) · rgba(139,92,246,…)
06

Status is colour-first

Badges do pair a tint with text, so meaning is not lost — but the label is 9–10px, which falls below the reading floor, so at a glance the tint alone is doing the work. Direction and live state need an icon, and every badge needs a 12px label.

03 · The proposed system

Tokens in three layers

Primitives hold raw values, semantic tokens give them a meaning, and component tokens give controls a default. A component never reads a primitive directly — that is what keeps a theme switch to one block of overrides.

Layer 1 · Primitive
31 values
Neutrals, blue ramp, status hues, categorical hues. Named by value, never by use.
Layer 2 · Semantic
47 tokens
Canvas, surfaces, borders, text, accent, status, chart chrome, focus. Same names in both themes.
Layer 3 · Component
7 groups
Button, field, card, table, KPI, nav, overlay, plus type / space / shape / motion scales.

Motion explains a state change, never decorates one. Entrances ease out, exits run at roughly 62% of the entrance and ease in, and list items stagger by 40ms.

04 · Components

The parts, with real states

Every specimen below is live HTML rendered with the tokens — not a screenshot. Specimens use Hebrew copy inside an RTL frame, because a component that only looks right in English is not finished.

4.1 Buttons

Six variants and three sizes. The primary is the only gradient surface in the product; the label is dark ink on both gradient stops. Every button gets a visible focus ring and a 44px default height.

Variants height 44 · radius 10 · 600 weight
  • Primary — one per view. Gradient #38bdf8 → #3b82f6, ink #04121f.
  • Secondary — the default action in a card toolbar; surface fill, hairline border.
  • Outline / quiet — low-emphasis actions. Quiet has no resting border.
  • Danger — tint for inline destructive actions; solid only for the final confirm.
  • Loading keeps the label and adds a spinner; disabled drops to 45% and keeps its shape.

05 · RTL & numerals

Right-to-left is a layout rule, not a translation

The page direction is set once on <html>. Everything else follows from logical properties, isolated number runs and a short list of icons that mirror.

Layout

  • Use padding-inline, margin-inline, inset-inline-start, border-inline-start. A physical left is a bug in waiting.
  • Flex and grid follow the writing direction automatically; never reverse a row by hand.
  • Scroll containers start at the right edge without extra code — no negative margins.
  • Decorative overlays anchor on one axis only (a badge uses top + inset-inline-end).

Numbers and currency

Do — isolate the run
Wrap the figure in a tabular, left-to-right run so the sign stays leading and the currency stays adjacent to the digits.
רווח נקי −₪1,240
תשואה +1.8R · +2.4%
Don't — format the sign last
Concatenating a minus after the digits, or leaving the run in the RTL paragraph, moves the sign to the wrong end when the string is isolated or copied.

תשואה 1.8R+

Mirrored icons

Icons that point along the reading direction mirror; icons that describe a physical object or a clockwise motion do not. This is the entire list — everything else is direction-neutral.

Sorting arrows point along the value axis (up = ascending) and never mirror. A back chevron points right in RTL, because “back” is to the right of the reading path.

Mixed strings

A pair name and a multiple can travel in one string. Isolate the Latin token and let the Hebrew sentence flow around it; do not reorder the text by hand.

Alignment

Text aligns to the inline-start edge. Numeric columns align to the same start edge with the number isolated, so digits line up on the right of the column and the sign stays at the leading edge of each figure.

06 · Accessibility

What is checked, and what is enforced

Every pair below is measured from the shipped token values. The system targets WCAG 2.2 AA: 4.5:1 for body text, 3:1 for large text, icons and essential graphics.

Focus

Visible focus2px accent · 2px offset

The ring is drawn outside the control so it never hides behind a card edge, and it uses the same accent in both themes so it is never mistaken for an error state.

Rules

  • Targets. Primary actions, fields and mobile controls are at least 44px tall. The 36px compact size is allowed only for secondary toolbar actions; icon-only buttons use the square icon variant.
  • Never colour alone. Status chips pair hue with text, and direction pairs hue with an arrow.
  • Type scaling. All sizes are in rem; a 200% root size must not clip a label or a table cell.
  • Motion. Reduced motion collapses every duration token to 1ms, including the shimmer and the ticker.
  • Names. Icon-only controls carry an accessible name; sortable headers expose aria-sort.
  • Contrast audit. Dark and light are checked independently — a passing dark token says nothing about light.

Order of work

  1. Ship the token file with aliases. Nothing renders differently; the old names resolve to the new values.
  2. Buttons and fields. Two primitives, the most repeated class strings, the biggest win.
  3. Cards, KPI and tabs. Collapse the radius and padding drift.
  4. Tables. Adopt the row, header and numeric-cell spec, then delete per-page overrides.
  5. Charts. Swap ad-hoc hexes for the categorical tokens and the shared tick style.
  6. Delete the aliases. Only after a search shows no call site reads the old names.

Retired

  • Violet in UI chrome — the light page glow and the sidebar active wash.
  • Text below 12px, including the 8px “New” and “LIVE” badges.
  • Hover states that grow a shadow or turn text lighter than its resting colour.
  • Gradient text on navigation labels — gradient is reserved for large numerals and the brand mark.
  • Backdrop blur on always-present cards; blur stays for transient overlays only.

Wiring it up

In Tailwind v4, point @theme at the semantic tokens rather than at raw hexes, so a utility class can never bypass the theme. The compatibility block at the end of tokens.css keeps today's --color-* names resolving while the migration runs.
